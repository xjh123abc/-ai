 当前阶段：AI 凭证端到端实施计划

> 目标：在当前阶段跑通账清 AI 的核心能力——基于已确认业务资料生成 AI 凭证草稿，由财务人员在前端判断、修正和审核，最后导出为待人工入账文件。每个目标只推进一个可独立验收的切片。

## 1. 当前阶段的产品目标

本阶段的核心交付是“业务证据 → DeepSeek 生成凭证草稿 → 前端人工判断 → 后端校验 → 人工审批 → 导出待人工入账”完整闭环。AI 必须参与凭证候选生成；现有本地规则候选不能冒充 AI 结果。

这里的“AI 自动做凭证”指自动生成供财务人员判断的凭证草稿，不代表自动审批或自动写入 ERP。AI 提供分录候选、摘要、会计理由和证据引用；后端按已确认来源及账套政策独立校验金额、科目、期间、辅助核算、借贷平衡和重复风险。前端是财务人员判断、修正及发起审核的工作台，不能替代后端校验。

## 2. 现有实现盘点

- 已有 `AccountingSuggestionProvider` 接口，以及 `FixtureRuleSuggestionProvider` 和 `ConfiguredAccountingSuggestionProvider` 两种本地规则实现；**尚无 DeepSeek provider，当前凭证候选不是 AI 生成**。
- 已有 `POST /api/v1/business-events/{event_id}/voucher-drafts` 生成并保存草稿；当前采购实现限于 45,200 元 fixture，费用、设备购置和租赁使用经确认的本地政策规则。
- 后端已有业务核对、凭证重复拦截、借贷平衡、账套科目、期间、政策版本及辅助核算相关检查；不同业务类型还有各自阻断条件。
- 前端已有凭证中心、来源引用和校验展示、凭证修正新版本、提交审核、不同人员审批、审计查看及 CSV 待人工入账导出。生成提示目前明确称为“规则候选”；后续应增量扩展为显示 AI provider、AI 理由与可查看的证据依据。
- 工作区存在未提交改动。每个目标开始前检查 `git status` 与相关 diff；不得重置、覆盖或清理这些改动。

## 3. 分阶段目标与退出条件

每次只启动一个目标。目标验收和复审通过后再开始下一个；外部服务不可用时记录阻塞及复现信息，不把规则候选、mock 或离线检查记作 DeepSeek 端到端通过。

### 阶段 A：DeepSeek 能力接入

**目标 A1：定义模型输入与凭证输出契约**

- 输入仅包含已人工确认的结构化业务字段、确定性核对结果、账套可用末级科目、已确认会计政策摘要及允许引用的来源 ID。
- 不发送原始票据、银行账号或完整合同；模型凭据只在服务端配置。
- 输出须包含候选分录（科目、借/贷金额、摘要）、逐行理由、证据引用、适用政策说明和警告；使用结构化校验，金额以十进制字符串承载。
- 退出条件：契约明确列出必填字段、允许引用范围及无效输出处理；不引入平行凭证 API。

**目标 A2：实现 DeepSeek provider 和安全调用**

- 在现有 `AccountingSuggestionProvider` seam 上新增 DeepSeek 实现，模型/服务端点和密钥通过服务端配置管理。
- 对超时、连接失败、限流、拒绝、无效 JSON 和结构校验失败返回可识别错误；禁止静默回退到本地规则。
- 审计 provider/model、提示模板版本、输入快照摘要、输出摘要及调用/校验结果，不记录密钥或完整敏感输入。
- 退出条件：可注入 provider 的 API 回归证明成功调用和各失败分支；缺少 DeepSeek 配置时明确提示不可用。

### 阶段 B：生成受约束的 AI 凭证草稿

**目标 B1：让现有生成接口调用 AI 并保存可追溯草稿**

- 保留现有 `POST /api/v1/business-events/{event_id}/voucher-drafts`，在业务、证据、政策和权限门槛通过后调用 DeepSeek。
- 校验来源引用只能指向当前业务明确关联的单据/已确认字段版本；核验科目属于当前账套有效末级科目。
- 后端基于确认后的来源金额和政策独立重算并比较模型金额，检查借贷平衡、期间、辅助核算、重复风险及业务特定约束。
- 校验失败不得生成可提交审核的草稿；证据不足或模型异常显示失败/待复核原因，不伪装为成功。
- 退出条件：草稿保存 provider/model 和输入来源快照，审计可追踪；原有幂等、版本和业务权限约束保持有效。

**目标 B2：前端展示 AI 凭证并支持财务判断**

- 在现有凭证详情上增量展示“AI 生成”、模型来源、逐行理由、引用证据入口、政策摘要和后端逐项校验结果。
- 财务人员可在现有编辑流程中修正分录，保存为新版本并重新校验；可退回或提交审核。修正后旧版本和 AI 原始建议可追溯。
- 校验不通过、证据缺失、AI 调用失败时，界面显示具体原因并禁用提交审核；不得仅靠前端计算判定通过。
- 退出条件：用户能从凭证行追到来源单据/字段证据，完成查看、修正、重校验及提交审核。

### 阶段 C：端到端主流程验收

**目标 C1：跑通 45,200 元采购主样例的 DeepSeek 凭证闭环**

- 使用现有采购金标样例：单据字段经人工确认，业务关系经用户确认且核对通过后，调用真实配置的 DeepSeek 生成候选。
- 前端查看三条分录、理由、来源和校验；覆盖财务接受原稿及修正后生成新版本两种路径。
- 由不同用户完成制单与审批，再导出 CSV；导出状态必须是 `EXPORTED_PENDING_MANUAL_POST`，明确 ERP 尚未写入。
- 退出条件：记录 API 与 Playwright 验收结果、DeepSeek 型号/配置标识、规则校验结果和失败处理；真实 DeepSeek 调用不可用时，此目标保持未通过。

**目标 C2：跑通失败与安全阻断回归**

- 覆盖模型超时/无效结构、未知科目、来源引用越权、金额与来源不符、借贷不平、辅助核算缺失、账期关闭、重复草稿、证据或政策不足。
- 验证失败时不产生可审批凭证、不导出为可入账状态、不绕过职责分离，并留下可追踪审计。
- 退出条件：API 回归和前端验收均证明阻断原因清晰且状态正确。

## 4. MVP 范围与边界

- **必须实现：** DeepSeek 生成凭证草稿、后端独立校验、前端人工判断与修正、人员审批、待人工入账导出。
- **首个业务闭环：** 先完成现有 45,200 元采购主样例；该 fixture 用于验证链路，不得宣称为通用采购会计规则。
- **后续独立切片：** 费用、设备购置、租赁、旧版发票、出租车、通行费和更多业务类型逐一接入并验收；其现有政策、证据或确认门槛不得为接入 AI 而放宽。
- **不在本阶段：** AI 自动审批、AI 直接写 ERP、无授权真实 ERP 联调、复杂租赁会计、以规则或 mock 冒充真实模型生成。
- **验收原则：** AI 提供会计候选，不构成正式账务真值；ERP 仍为正式账务来源。模型建议无法通过确定性校验时必须阻断，不能以“模型认为合理”放行。

## 5. 执行约定

每个目标开始前检查未提交改动和目标相关接口；只改该目标所需范围。完成后运行该切片相关 API/UI 验收，复审需求符合度和代码标准，并记录通过项、未验证项及阻塞。测试结果必须区分本地规则、mock provider 与真实 DeepSeek provider。不得将未完成的后续目标并入正在执行的目标。

## 6. 阶段 A 实施记录（2026-10-27）

- **A1 已完成：** 定义 `VoucherSuggestionContext` 输入契约，限制字段为已确认的结构化业务类型、金额/日期/类别/状态代码、核对代码、可用账套科目、政策摘要和允许的证据引用；拒绝未知字段、非结构化政策值及不匹配金额。
- **A2 provider 已实现：** 新增 DeepSeek Chat Completions provider，服务端配置项为 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`DEEPSEEK_TIMEOUT_SECONDS`。本地 `.env` 含 API Key 和 URL 配置项，模型默认 `deepseek-flash`；URL 可填服务 base URL 或完整 `/chat/completions` URL；远程地址必须使用 HTTPS，本机回环地址可使用 HTTP。凭据值不写入本文档或日志。
- provider 使用 JSON 输出，验证 JSON 结构、金额、候选科目及证据引用；来源引用在发送前必须为不含自由文本的 UUID。远程请求要求 HTTPS、禁止自动跟随重定向；错误信息不暴露请求体、响应体或密钥。只通过显式传入的脱敏结构化上下文构造请求，不发送原始单据内容。
- provider 输出要求包含逐行理由和适用会计政策说明；provider 接口返回安全 trace，包含 provider/model、prompt 版本、输入/输出摘要哈希及调用/校验状态。该 trace 尚未接入持久审计流。
- provider seam 定向测试覆盖成功解析、缺少配置/上下文、模型拒绝、未知科目、越权/非 UUID 来源引用、无效金额、远程 HTTP 拒绝、HTTP 401/429、超时、连接失败、无效 JSON、敏感字段拒绝、防重定向和安全 trace 信息；这些测试尚未替代计划要求的 API 路由级 provider 注入回归。
- **A2 尚未验收完成：** 缺少 API 路由级注入回归和持久化 provider 审计。DeepSeek API Key 与 URL 已在本地 `.env` 配置，但未发起真实模型调用；凭证生成路由尚未切换至 DeepSeek。阶段 A 不代表 AI 凭证端到端链路已验收。
