# ADR-0001：凭证写入编排与外部连接器边界

- 状态：已采纳
- 日期：2026-10-27

## 背景

产品需要保留 ERP 为正式账务真值的原则。ERP 授权和目标账套尚未取得，因此当前只能提供待人工入账导出，同时需要先把将来可安全验收的接口和状态规则定义清楚。

## 决策

- `packages/connectors` 只定义连接器契约和文件导出 adapter。ERP 实现必须显式提供能力、授权、幂等查询、提交和写后读回；当前没有注册真实连接器或 ERP 凭据。
- `packages/posting` 负责通用写入编排：只接受由后端从已审批凭证版本构造的命令；要求连接器具备文档、读写授权和幂等能力；先持久保留唯一写入尝试，再发送外部请求；超时或进程中断后只回查、不盲目重发；只有读回期间、借贷合计和每条分录与批准版本一致才可返回 `VERIFIED`。
- 编排器通过 `AccountingConnector` 和持久尝试记录接口依赖连接器及存储，不直接依赖 HTTP/FastAPI，也不自行决定权限。API 调用方负责租户授权、角色、审批状态和事务边界。
- `services/api` 持有 `posting_attempts` 持久记录：企业/账套、凭证 ID 与版本、幂等键、请求摘要/快照、状态、操作者、外部凭证引用和审计事件。已批准凭证仍是该业务唯一凭证来源；尝试记录不是总账或第二套凭证账本。
- `packages/vouchers` 继续生成凭证草稿和版本；它不写入 ERP，也不保存 ERP 正式账务。ERP 始终是正式记账真值来源。
- 当前导出走通用 CSV adapter，状态为 `EXPORTED_PENDING_MANUAL_POST`。真实 ERP 连接、写入路由和生产写回保持关闭，取得明确授权并通过隔离测试账套验收后才能启用。

## 后果

- 可用模拟 connector 验收授权拒绝、幂等占位、超时回查、逐行核对和 UNKNOWN 状态，而不触达任何真实 ERP。
- API 数据库迁移创建 `posting_attempts` 并追加审计；恢复旧的 UNKNOWN/SUBMITTING 尝试只能回查，无法确认时交由人工处理。
- 真实 connector 的协议差异、账号版本和沙盒行为仍需授权后逐一实现和验证；通用 CSV 模板不代表目标 ERP 可直接导入。
