# 账清 AI｜前端信息架构与交互 V2

目标：让用户一眼知道「我今天要处理哪些单据、AI 生成了哪些凭证、哪些已真正入账、哪些需要我决定」；旧版以“异常工单”为唯一主线的 UI 调整为完整 AI 财务运营工作台。

## 1. 主导航

```text
账清 AI
├── 财务工作台                 首页 /workspace
├── 单据中心                   上传及识别 /documents
├── 业务中心                   多文件关联 /business-events
├── 凭证中心                   生成、校验、审批、写回 /voucher-drafts
├── 核对与异常                 旧的任务工作流 /cases
├── 财务分析                   指标与问答 /insights
└── 连接与设置                 ERP 状态、账套科目、会计政策 /integrations
```

保留旧的蓝白视觉、左侧导航、顶部企业/账套/期间、右侧详情抽屉、金额表格与状态标签，但主首页从“异常事项列表”改为“待处理财务事务 + 处理进度”。

## 2. 工作台首页

顶部：企业/账套/期间选择与数据来源状态。首屏：

- 主 CTA：**上传单据开始处理**（可拖拽发票/入库/回单/合同等）。
- 第一行 KPI：未识别单据、待关联业务、待审核凭证、已成功核实入账、写回失败/未知。数值必须从真实后端且经过权限过滤得出。
- 第二行「最近处理的业务」列表：业务编号、供应商/客户、总额、关联单据数、业务状态、凭证状态、ERP 状态和“继续处理”。
- 右侧/下方「需要关注」：票款不一致、重复发票、审批退回、ERP 返回未知、缺入库证据。
- 轻量资金/费用摘要仅基于真实有权读取的数据；没有数据时明确提示“尚未连接/资料不足”，不造一个利润值。

## 3. 单据中心

页面顶部“批量上传”按钮+拖拽区域，支持进度与失败重试。表格列：缩略图、类型、上传时间、来源、识别状态、关键金额、所属业务、缺失字段。

打开单据使用左右并列：

- 左：原始票据图像/PDF 预览，可缩放/翻页；
- 右：提取字段表单（企业、票号、税额、价税合计、日期、合同/订单号等），标记“自动识别/人工确认/识别失败”；
- 点击右侧字段，高亮左侧来源区域（没有 bbox 时不伪造高亮，退化到页面级引用）；
- “确认字段并进入业务关联”，保存人工修正与原值；
- 多页合同、验收报告能够完整浏览，不能只上传第一页。

## 4. 业务中心

每张卡片或列表行代表**一笔业务**，不是某一个 OCR 文件。

详情布局：

1. 业务摘要：类型、对方公司、金额、日期、来源覆盖；
2. 证据时间轴/分组：合同 → 入库/验收 → 发票（一张或多张） → 支付证明 → 银行回单；
3. 关联理由与状态：强证据、候选、冲突、缺失；用户可明确确认/拆分/补件；
4. 核对结果：价税、数量、往来、付款是否一致，解释和来源字段；
5. 主 CTA：**生成凭证草稿**，仅在证据足够且无阻断风险时可继续；否则显示待处理问题。

不要把“银行付款通知”误显示为“已银行清算”，不要把多张同一批上传的独立发票自动合成同一笔业务。

## 5. 凭证中心（首版必需）

列表标签：草稿、待补资料、待审核、已批准、提交中、入账待核实、已核实入账、失败/未知、已导出待人工入账。

凭证详情：

- 左侧业务凭证摘要+单据缩略图、来源引用、AI 判断依据；
- 中间标准会计分录表：摘要、借方科目、借方金额、贷方科目、贷方金额、辅助核算、政策前提；默认显示借贷合计；显示所用政策版本、确认人及税额处理口径，fixture 规则明确标注仅供测试；
- 下方规则检查区：借贷平衡、有效科目、税额/进项、会计期间、重复风险、证据覆盖；
- 明显区分“AI 建议”“财务已批准”“ERP 已写入并回读确认”；
- 有权限用户可以修改草稿科目/摘要并重新校验，修改后需要重新审批；
- “提交审核”“批准”“写入 ERP”“导出凭证”按钮按状态与权限显示。

**写入 ERP 前必须有明确确认步骤**，展示目标账套、期间、分录、总额、审批人、重复入账风险与可审计提示。

成功页须展示 ERP 凭证号、写入时间、回查状态；仅 API 接收成功不能写“已核实”。超时展示“结果未知，正在核查/请联系管理员”，不允许用户直接盲目再提交。

## 6. 异常与分析（复用旧模块）

旧异常抽屉保留事实、推测、缺失资料、差额、负责人和操作轨迹，作为业务审核阻断的跳转页面。异常解决后可回到原业务继续生成/审核草稿。

财务分析视图按真实可得数据展示本期收支、费用类别、应收应付、关键风险与最近对账差异。所有指标必须带期间、账套、数据截至时间和证据下钻入口；数据不全要显示口径说明。AI 问答不得编造缺失的银行余额或利润数据。

### 6.1 连接与账套设置

- 显示 ERP 的实际连接和授权状态；未授权时明确说明只能导出待人工入账文件。
- TENANT_ADMIN 可维护当前账套科目编码、名称、启用/末级状态和必填辅助核算维度。
- TENANT_ADMIN 与 ACCOUNTANT 可按费用报销、设备购置、租赁配置借方科目、付款科目和进项税处理，并明确勾选财务负责人已核定；设置页需显示当前政策版本和业务类型。
- 仅允许选择当前有效末级科目。租赁首版仅支持明确确认的直接费用处理；财务人员在建立租赁业务时须逐笔确认已核对合同并确认适用当前账套的直接费用政策，系统记录确认人及政策版本。缺少确认或确认对应的政策版本已变化时保持待复核并阻止制证；其他租赁会计处理应提示暂不支持并保持待复核。政策或科目不可用时不得生成可提交凭证。

## 7. 前端组件与状态

推荐复用：`AppShell`、`AccountSetSwitcher`、`EvidenceDrawer`、`CaseDrawer`、`ErrorBoundary`、金额格式化与权限组件。

新增/改造：

- `DocumentUploadBatch`、`DocumentPreview`、`ExtractedFieldsPanel`；
- `BusinessEventList`、`DocumentRelationshipGraph`、`ReconciliationPanel`；
- `VoucherDraftTable`、`VoucherValidationChecklist`、`VoucherApprovalPanel`；
- `PostingStatusTimeline`、`ERPConnectionCapabilityBadge`、`EvidenceLinkedInsight`。

服务端是业务状态真值；前端只管理抽屉/筛选/未保存草稿等临时状态。新页面必须具备：加载、空数据、无权限、解析失败、ERP 未授权、网络断开、写账未知、重试提示。

## 8. 端到端验收场景

1. 新用户登录且未接入账套：有明确“上传样例/配置账套”入口，**不得展示虚构交易量**。
2. 批量上传 45,200 元三张原始单据：看到识别状态、字段来源及三者已关联。
3. 打开业务详情 → 看到核对结果 → 点击生成凭证 → 查看并校验三条分录。
4. 会计提交、财务负责人批准；在授权测试账套写回并回查；未授权展示导出方式而不是模拟已入账。
5. 上传一张付款冲突的发票/回单：显示待复核，相关问题与引用清楚，禁止跳过校验。
6. 移动端不需要先做全部 ERP 能力，但主流程、单据预览、审批状态至少可读可用。

说明：以上是前端交互与逻辑要求，不代表旧 HTML 预览已有这些页面；Codex 必须检查 `apps/web/` 实际版本后最小增量修改。
