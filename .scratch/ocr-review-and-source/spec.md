# OCR 字段核对与来源显示

## Problem

OCR 原文已有日期、金额等内容时，未分类单据的核对界面仍展示空的通用字段，用户看不到已提取的单据专属候选值。单据列表重复显示历史关联业务，凭证每条分录重复显示同一组来源单据。

## Solution

- 对尚未人工分类的单据，若存在明确的类型建议，核对表单先按建议类型展示对应字段及已提取候选值；仍须人工核对并保存，类型建议不自动成为确认事实。
- 对旧版待确认单据，读取详情时可从已保存的 OCR 原文与位置重新生成缺失候选；保留历史字段版本原样，不覆盖已确认字段。
- 单据列表每份单据只显示最新的一条关联业务，并在该区域水平、垂直居中。
- 凭证详情在分录表外只显示一处来源单据列表。来源文件可直接打开原件预览，保留证据字段与确认版本追溯。
- 凭证标题按记录的 provider 如实标明 AI 生成或普通凭证建议，避免测试规则候选被误称为 DeepSeek 生成。
- 说明三张采购单据的实际 OCR 字段候选、验收期望值和 DeepSeek 生成路径的区别。

## Decisions

- 最新关联业务按业务事件创建时间排序，同一时间以 ID 稳定排序；不删除历史关联数据。
- 继续使用现有带鉴权的单据预览 API，避免把原件暴露为公开 URL。
- 凭证生成仍使用当前 provider 配置；不因 OCR 候选而跳过人工确认或后端核验。

## Testing decisions

- 已同意的主要验收界面：上传三张采购样例，核对字段候选和原件，生成凭证，查看唯一来源区块。
- 字段提取单测用于定位 OCR 回填问题；它不能证明运行中数据库里某笔单据的保存版本或真实 DeepSeek 请求。
- 前端行为测试确认未分类单据采用类型建议后的字段展示、最新关联业务只显示一条、凭证来源只显示一处并可查看原件。

## Out of scope

- 不把未确认 OCR 候选直接用于制单，不自动认定银行清算或入库状态。
- 不更改科目政策或 ERP 入账流程。
