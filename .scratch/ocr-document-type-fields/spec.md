# 票据 OCR 字段映射与类型判断

### Problem

OCR 原文中已经包含单据名称、单位、数量、单价、金额和用途等信息，但部分值没有进入对应的关键字段；人工改选单据类型后，候选字段与原文位置证据也可能没有完整保存在确认版本中。发票类型建议还可能忽略票面表头，把增值税专用发票误判成普通发票。

### Solution

按 OCR 原文、行坐标和单据表头，将能够明确识别的值映射到对应单据类型的关键字段。字段值保留原始 OCR 文本、页码和位置证据；歧义字段留待人工核对。用户改选类型后按新字段组重新匹配，并在保存确认版本时保留候选证据。

票据标题用于判断发票类型，优先级高于页面下方的图注或普通文本。识别到“增值税专用发票”时建议专用发票并展示其字段组；候选仍需人工确认。

### User stories

- 作为财务人员，我希望 OCR 已识别且能明确对应的值出现在正确关键字段中，这样我不必重复录入。
- 作为财务人员，我希望每个候选值都能定位回原件，并在保存确认后继续保留证据，这样我能核验识别与映射。
- 作为财务人员，我希望发票类型建议依据票面标题，这样专用发票字段不会被普通发票字段组遮蔽。

### Decisions

- 适用类型为普通发票、增值税专用发票、入库单、支付证明和银行电子回单；对照页展示、API 可保存范围和缺失字段提示使用相同字段组。
- 入库单的商品名称、单位、数量、单价和金额分别对应其表格列；45,200 元金额不能映射为单价。发票示例中单价为 400.00、未税金额 40,000.00、税额 5,200.00、价税合计 45,200.00。
- 所有字段值都以对应原件的 OCR 结果为准；口述示例只用于定位要核查的字段，不得覆盖 OCR 识别值或成为固定映射值。相同数字出现在不同字段时，按票面标签和列位置分别归属。
- 支付证明的“科目”映射到费用科目，“事由或品名”映射到报销事由。银行电子回单的“用途/摘要”映射到交易摘要，“业务种类”映射到业务种类。
- 类型建议和字段候选保持待核验状态，不能自动视作人工确认。字段值无法唯一对应时留空，不用金额总数、标题或相邻列猜单价、单位或状态。
- 用户改选类型后用同一份 OCR 原文重新生成该类型候选。保存确认版本时保留候选的原文、页码、坐标和证据文本，同时记录人工确认值与字段变更历史。
- 不更换 OCR 模型，不承诺未覆盖票面版式上的全量识别准确率。

### Testing decisions

已同意的验收接缝：使用原始样例图跑 OCR，再从 OCR 原文和坐标检查类型候选、字段值及证据；通过确认接口保存后读回确认版本和历史证据，并核对字段组在确认页的展示。覆盖入库单商品/单位/数量/单价/总额、支付证明科目/事由、银行回单用途/业务种类，以及增值税专用发票表头优先级。该接缝验证提供样例的端到端映射，不保证所有未见版式。

### Out of scope

- 更换或训练 OCR 模型，以及对任意票据版式作准确率承诺。
- 改动业务核对、凭证生成、审批或 ERP 入账流程。
- 扩展上述类型以外的单据字段组。
