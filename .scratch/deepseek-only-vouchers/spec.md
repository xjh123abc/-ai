# 只由 DeepSeek 生成凭证科目

## Problem

旧的 45,200 元测试规则直接写死 1405、222101、1002，并在部分界面中被误认为 AI 生成。采购制证路径还隐含固定科目及税务处理假设。

## Solution

- 凭证生成只调用 DeepSeek；输入已人工确认的单据结构化事实、当前账套有效末级科目、相关会计政策及来源 ID。DeepSeek 返回科目编码、金额、理由和来源引用，后端核查后保存。
- 删除固定科目规则 provider 和采购默认科目、税务处理假设。未配置采购政策时，不把它伪装为已确认政策；模型可从有效科目表提出候选，由财务人工审核。
- DeepSeek 未配置、调用失败、响应无效时明确失败，不生成本地规则替代凭证。
- 删除当前账套已经保存的 `LOCAL_FIXTURE_RULES` 和旧版 `RULE_CANDIDATE` 凭证及其分录、审批；保留删除操作的审计记录。已导出的 CSV 原本仅作为下载流返回，服务器未保存副本。
- 对 45,200 元已确认业务真实调用 DeepSeek，确认新凭证记录中的 provider 和成功 trace。

## Testing decisions

- 核心验收以真实制证 API 与已保存的凭证 provider/trace 为准，不能只看 UI 文案。
- API 测试可注入明确标记的假模型响应检验失败阻断、科目范围和证据校验；测试替身不得在实际运行中成为回退路径。
- 真实 DeepSeek 调用结果可能因服务、科目和模型输出不同而变化；失败时不预填科目或自动改用规则。
